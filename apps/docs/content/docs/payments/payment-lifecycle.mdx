Each payment has exactly one `status` at any moment. This page documents every status, what moves a payment between them, and which [webhook events](/docs/integration/webhooks) fire so your system can stay in sync.

## Status reference

<TypeTable
  type={{
    pending: { type: "status", description: "Created, awaiting customer action or processing." },
    requires_authentication: { type: "status", description: "Customer must complete 3D Secure / SCA." },

    completed: { type: "status", description: "Funds captured and credited toward your balance." },
    failed: { type: "status", description: "Declined or could not be processed." },
    cancelled: { type: "status", description: "Voided before capture." },
    refunded: { type: "status", description: "Fully returned to the customer after completion." },
  }}

## State diagram

```
            ┌───────────────┐
            │    pending    │
            └──────┬────────┘
        ┌──────────┼─────────────────┐
        ▼          ▼                 ▼
requires_      processing         cancelled
authentication     │
        │          ▼
        └────► completed ──► refunded
                   │
                 failed
```

## Terminal vs. non-terminal states

- **Non-terminal** (`pending`, `requires_authentication`, `processing`) — the payment may still change. Never fulfil an order in these states.
- **Terminal** (`completed`, `failed`, `cancelled`, `refunded`) — the outcome is settled. `completed` is the only state in which you should fulfil. `refunded` is reachable only from `completed`.

<Callout type="warn">
Fulfil on the `payment.completed` **webhook**, not on the synchronous API response. A payment can still require authentication after creation.
</Callout>

## Webhook events per transition

| Transition | Event |
|---|---|
| → `requires_authentication` | `payment.requires_authentication` |
| → `processing` | `payment.processing` |
| → `completed` | `payment.completed` |
| → `failed` | `payment.failed` |
| → `cancelled` | `payment.cancelled` |
| → `refunded` | `payment.refunded` |

```typescript
export async function POST(req: Request) {
  const event = vinr.webhooks.verify(
    await req.text(),
    req.headers.get('x-vinr-signature'),
  );

  if (event.type === 'payment.completed') {
    await fulfillOrder(event.data.metadata.orderId);
  }
  return new Response('OK', { status: 200 });
}
```

## Idempotency & retries

Webhook delivery is at-least-once, so the same event may arrive more than once. Make handlers **idempotent** — key on `event.id` and ignore duplicates. When creating payments, send an [idempotency key](/docs/integration/idempotency) so a retried request never double-charges.
