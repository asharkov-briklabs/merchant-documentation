Payment links let you collect a payment without writing code — create a link, share the URL or QR code, and VINR hosts the entire checkout. They are ideal for invoices over email, social bios, point-of-sale QR codes, and quick one-off requests where standing up a checkout page would be overkill.

## How a link works

A payment link wraps the same `payment` model described in [How payments work](/docs/payments/how-payments-work). When a customer opens the link, VINR creates a fresh `payment` behind the scenes, runs hosted checkout, and redirects to your `returnUrl` (or a default thank-you page) on completion. You never touch card data, and every method enabled on your account — cards, SEPA, iDEAL, stablecoins — appears automatically.

```
share link → customer opens → VINR creates pay_… → hosted checkout → returnUrl + webhook
```

## Creating a link

Create links from the [Dashboard](/docs/operations) under **Payments → Links**, or from the API. The API returns a `url` you can paste anywhere and a `qrCodeUrl` for print or screen.

```typescript
import { Vinr } from '@vinr/sdk';

const vinr = new Vinr({ secretKey: process.env.VINR_SECRET_KEY });

const link = await vinr.paymentLinks.create({
  amount: 4500,                 // €45.00 in minor units
  currency: 'EUR',
  description: 'Studio session — 1 hour',
  returnUrl: 'https://yoursite.com/thanks',
  reusable: true,               // accept many payments on one link
  metadata: { source: 'instagram-bio' },
});

// link.id         → "pal_7Qk2m9..."
// link.url        → "https://pay.vinr.com/l/7Qk2m9"
// link.qrCodeUrl  → PNG render of the same URL
```

<Callout type="warn">
Amounts are integers in the currency's smallest unit: `4500` is €45.00, not €45. To let the customer enter their own amount (tips, donations), omit `amount` and set `amountEditable: true`.
</Callout>

## Customizing the link

Links inherit your account branding (logo, colors, business name). Per-link options let you tailor what the checkout collects and how it behaves.

## One-time vs. reusable

The `reusable` flag is the single most important choice when creating a link.

<Tabs items={["One-time", "Reusable"]}>
<Tab value="One-time">

A one-time link accepts exactly one successful payment, then closes. Use it for a specific invoice or a single sale where a second charge would be a mistake.

```typescript
const invoiceLink = await vinr.paymentLinks.create({
  amount: 12000,                // €120.00
  currency: 'EUR',
  description: 'Invoice 2026-0418',
  reusable: false,              // closes after first success
  expiresAt: '2026-06-30T23:59:59Z',
});
```

</Tab>
<Tab value="Reusable">

A reusable link stays open and creates a new `payment` for every visitor — perfect for a donation page, a product in a bio, or a counter QR code. Bound it with `maxPayments` or `expiresAt` when you need a hard stop.

```typescript
const donateLink = await vinr.paymentLinks.create({
  currency: 'EUR',
  description: 'Support our work',
  amountEditable: true,         // donor picks the amount
  reusable: true,
  maxPayments: 1000,
});
```

</Tab>
</Tabs>

## Tracking conversions

Each link exposes lifetime counters, and every resulting payment fires the same webhook events as any other charge. Listen for `payment.completed` and read the link reference plus your `metadata`.

```typescript
app.post('/webhooks/vinr', async (req, res) => {
  const event = vinr.webhooks.verify(
    req.rawBody,
    req.headers['x-vinr-signature'],
  );

  if (event.type === 'payment.completed') {
    const { id, amount, paymentLinkId, metadata } = event.data;
    console.log(`Paid ${amount} via link ${paymentLinkId}`, metadata);
    // attribute the sale, fulfill the order, etc.
  }

  res.sendStatus(200);
});
```

Read aggregate stats at any time with `vinr.paymentLinks.retrieve('pal_…')`, which returns `paymentsCount` and `amountCollected`. Use `metadata` (e.g. `source`) to attribute conversions to a channel. See [Webhooks](/docs/integration/webhooks) for delivery and retry behavior.

## Limitations

<Callout type="info">
Payment links cover one-off collection. For recurring charges, model the link as a subscription checkout via [Billing](/docs/billing); links themselves do not create subscriptions.
</Callout>

- One link charges in a single currency. Sell across currencies with separate links.
- `authorize`-only (delayed capture) is not supported on links — payments are captured immediately. Use the [API flow](/docs/payments/authorize-and-capture) when you need a hold.
- Editable amounts respect your account minimum and a per-link `maxAmount` you can set to prevent typos.
- Disputes, refunds, and settlement work identically to any other payment — manage them in [Operations](/docs/operations).
