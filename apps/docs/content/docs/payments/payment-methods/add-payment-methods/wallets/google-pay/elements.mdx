<Callout type="warn">
**Not yet available.** Google Pay via VINR Elements (the `GooglePayElement` shown below) is not yet released. To accept Google Pay today, use [hosted checkout](/docs/payments/payment-methods/add-payment-methods/wallets/google-pay/hosted-checkout) — automatic, no code — or the [direct Google Pay API integration](/docs/payments/payment-methods/add-payment-methods/wallets/google-pay/setup). The steps below describe the planned Elements integration.
</Callout>

VINR Elements is the component library for building a custom checkout UI inside your own page. You mount individual UI components — card fields, address collectors, wallet buttons — and VINR handles tokenization, 3DS, and submission. Once available, adding Google Pay to an Elements checkout will require mounting a single `GooglePayElement`; you will not implement the Google Pay JavaScript API directly.

## Prerequisites

- Google Pay enabled on your VINR merchant account (**Settings → Payment methods**).
- VINR Elements loaded on your page.
- Acceptance of Google's terms: to use Google Pay you **must** accept the [Google Pay API Terms of Service](https://payments.developers.google.com/terms/sellertos) and **must** comply with the [Google Pay API Acceptable Use Policy](https://payments.developers.google.com/terms/aup).

## Integration

### 1. Initialize VINR Elements

Obtain a `clientSecret` from a server-side `vinr.payments.create` call, then pass it to `vinr.elements`.

```javascript
import { loadVinr } from '@vinr/sdk';

const vinr = await loadVinr('YOUR_VINR_PUBLISHABLE_KEY');
const elements = vinr.elements({ clientSecret: 'YOUR_CLIENT_SECRET' });
```

### 2. Mount the GooglePayElement

Create and mount the wallet button element. VINR calls `isReadyToPay` internally — the element renders only when the customer's device is eligible.

```javascript
const googlePayElement = elements.create('googlePay', {
  style: {
    theme: 'black', // 'black' | 'white'
    type: 'buy',    // 'buy' | 'pay' | 'checkout' | 'subscribe' | 'donate' | 'plain'
  },
});

googlePayElement.mount('#google-pay-button');
```

```html
<div id="google-pay-button"></div>
```

### 3. Handle the payment

Listen for the `completed` event. When the customer authenticates in the Google Pay sheet, VINR calls your handler. Call `confirmPayment` to complete the transaction.

```javascript
googlePayElement.on('completed', async (event) => {
  const { error } = await vinr.confirmPayment({
    elements,
    confirmParams: {
      return_url: 'https://yoursite.com/order/complete',
    },
  });

  if (error) {
    document.getElementById('error-message').textContent = error.message;
  }
  // On success, VINR redirects to return_url
});
```

VINR handles all 3DS challenges and the PAN_ONLY step-up automatically. If a challenge is required, the customer completes it in a modal managed by VINR Elements before the redirect fires.

The `GooglePayElement` sets Google Pay's `tokenizationSpecification` and billing address requirements internally. These values are not configurable through the element:

| Property | Value |
|---|---|
| `gateway` | `vinrpay` |
| `gatewayMerchantId` | your VINR account ID |
| `billingAddressRequired` | `true` |
| `billingAddressParameters.format` | `FULL` |
| `billingAddressParameters.phoneNumberRequired` | `true` |

See [Set up Google Pay (API)](/docs/payments/payment-methods/add-payment-methods/wallets/google-pay/setup#tokenization-specification) for the full tokenization details and [billing address](/docs/payments/payment-methods/add-payment-methods/wallets/google-pay/setup#billing-address) requirements.

## Showing Google Pay alongside card fields

Mount the `GooglePayElement` and `CardElement` (or `PaymentElement`) in the same Elements instance. VINR renders the wallet button only when the device is eligible, so the layout degrades gracefully for customers who cannot use Google Pay.

```javascript
// Both elements share the same `elements` instance
const cardElement = elements.create('card');
cardElement.mount('#card-element');

const googlePayElement = elements.create('googlePay');
googlePayElement.mount('#google-pay-button');
```

<Callout type="info">
Place the Google Pay button on visual parity with your card input — not smaller or hidden. Google's brand guidelines require wallet buttons to receive equal prominence with other payment methods.
</Callout>

## Content Security Policy

Every VINR Element — including the `GooglePayElement` — renders inside an `<iframe>` served from VINR's domain, not yours. If your page sends a `Content-Security-Policy` header, the browser blocks that iframe unless you explicitly allow it.

- Add the VINR Elements iframe origin (the `secureFormsUrl` value provided to you during onboarding) to your `frame-src` directive (and `child-src`, for older browsers):

  ```
  frame-src 'self' https://elements.vinr.com;
  child-src 'self' https://elements.vinr.com;
  ```

- `@vinr/elements` is an npm package that you bundle into your own JavaScript — it is not loaded from a remote `<script>` tag, so it does not require a `script-src` allowance.
- Data moves between your page and the iframe over `postMessage`, not `fetch`/`XHR`, so the Google Pay handshake itself does not require a `connect-src` change.

<Callout type="warn">
The exact iframe origin differs between VINR's sandbox and production environments and is assigned to you during onboarding. Confirm the correct value with your VINR contact before updating your CSP — do not guess or hardcode a domain.
</Callout>

## Testing

Point your integration at your VINR **sandbox** account. In test mode, VINR passes `TEST` to the Google Pay client internally — no Google Pay environment configuration is needed on your side.

See [Test & go live](/docs/payments/payment-methods/add-payment-methods/wallets/google-pay/test-and-go-live) for the test card reference covering both `CRYPTOGRAM_3DS` and `PAN_ONLY` scenarios.
