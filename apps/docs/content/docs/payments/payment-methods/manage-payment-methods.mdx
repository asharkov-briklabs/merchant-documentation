Saving a payment method to a Customer lets you charge them later without re-entering card details — essential for subscriptions, one-click reorders, and off-session charges.

## Save during a payment

Add `setup_future_usage` to a PaymentIntent to save the payment method used for that charge:

- **`on_session`** — saves the method for future checkouts where the customer is present on your site.
- **`off_session`** — saves the method for background charges (subscriptions, reorders) where the customer will not be present. VINR requests stronger authentication upfront so the future charge can proceed without friction.

```ts
import { Vinr } from '@vinr/sdk';

const vinr = new Vinr({ apiKey: process.env.VINR_SECRET_KEY });

const paymentIntent = await vinr.paymentIntents.create({
  amount: 2900,
  currency: 'usd',
  customer: 'cus_ABC123',
  setup_future_usage: 'off_session', // or 'on_session'
  automatic_payment_methods: { enabled: true },
});
```

## Save without charging (SetupIntent)

Use a SetupIntent when you want to collect and vault a payment method without charging immediately — for example, at trial sign-up or when adding a card on file.

1. Create the SetupIntent server-side and return the `client_secret` to your front end.
2. Confirm the SetupIntent client-side using the Payment Element.
3. On success, store the returned `payment_method` ID against the customer record.

```ts
// Server: create the SetupIntent
import { Vinr } from '@vinr/sdk';

const vinr = new Vinr({ apiKey: process.env.VINR_SECRET_KEY });

const setupIntent = await vinr.setupIntents.create({
  customer: 'cus_ABC123',
  usage: 'off_session',
});

// Return setupIntent.client_secret to the client
```

```ts
// Client: confirm with the Payment Element
const { error } = await elements.submit();
if (!error) {
  await vinr.confirmSetup({
    elements,
    clientSecret: setupIntent.client_secret,
    confirmParams: { return_url: 'https://example.com/setup-complete' },
  });
}
```

## Reusable vs single-use methods

| Method | Reusable | Notes |
|---|---|---|
| Cards | Yes | Can be re-confirmed unlimited times |
| Bank debits (ACH / SEPA) | Yes | Requires mandate acceptance at setup |
| Bank redirects (iDEAL, Bancontact) | No | Single-use; save the resulting bank account instead |
| Bank transfers | No | Each transfer is a separate instruction |

For iDEAL and Bancontact, VINR automatically generates a reusable SEPA Direct Debit mandate after the first redirect. Retrieve it from the PaymentMethod's `sepa_debit` field and use that for future charges.

## List and detach

List all saved payment methods for a customer:

```ts
import { Vinr } from '@vinr/sdk';

const vinr = new Vinr({ apiKey: process.env.VINR_SECRET_KEY });

const methods = await vinr.customers.listPaymentMethods('cus_ABC123', {
  type: 'card',
});
```

Detach a method when a customer removes a saved card from their account:

```ts
await vinr.paymentMethods.detach('pm_XYZ789');
```

Detaching removes the method from the customer and prevents it from being charged.

<Callout type="warn">
  Never store raw card numbers. PaymentMethod IDs (`pm_...`) are safe to store — they reference tokenized data held entirely within VINR's PCI-compliant vault.
</Callout>
