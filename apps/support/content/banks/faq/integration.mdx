## API Integration

### What programming languages are supported?

Our API is REST-based and works with any language that can make HTTPS requests. We provide SDKs for:

- Node.js
- Python
- Java
- PHP
- Ruby
- .NET

### What is the API base URL?

**Production**: `https://api.vinr.com/v1/bank`  
**Sandbox**: `https://api-sandbox.vinr.com/v1/bank`

### How do I authenticate API requests?

Use HTTP Basic Auth with your API credentials:

```bash
Authorization: Bearer bk_live_YOUR_API_KEY
```

Or using API key and secret:

```bash
curl https://api.vinr.com/v1/bank/transactions \
  -u bk_live_KEY:SECRET
```

### What are the rate limits?

- **Production**: 100 requests/second, 10,000/hour
- **Sandbox**: 50 requests/second, 5,000/hour

Exceeding limits returns HTTP 429. Implement exponential backoff.

### How do I handle API versioning?

The API version is in the URL (`/v1/`). We maintain backward compatibility within major versions. Breaking changes require new major version.

## Authorization & Settlement

### How quickly must I respond to authorization requests?

Response time requirements:

- **Target**: `< 1 second`
- **Maximum**: 3 seconds
- Slower responses may be timed out

### What information is included in authorization requests?

- Merchant ID
- Transaction ID
- Amount and currency
- Card details (tokenized or raw)
- Billing address
- 3D Secure data (if applicable)
- Metadata

### How are partial captures handled?

You must support:

- Full capture (100% of authorized amount)
- Partial capture (less than authorized)
- Multiple partial captures (if supported)

### When are settlements processed?

- **Cut-off**: 23:59 UTC daily
- **Batch creation**: 00:00 UTC
- **Settlement**: T+2 business days

## Webhooks

### What webhook events should I expect?

Events sent to your endpoint:

- `merchant.verified` - New merchant approved
- `settlement.initiated` - Settlement batch started
- `chargeback.received` - Chargeback notification
- `dispute.created` - Payment dispute

### How do I verify webhook signatures?

```javascript
const crypto = require('crypto');

function verifyWebhook(payload, signature, secret) {
  const expectedSignature = crypto
    .createHmac('sha256', secret)
    .update(payload)
    .digest('hex');
  
  return crypto.timingSafeEqual(
    Buffer.from(signature),
    Buffer.from(`sha256=${expectedSignature}`)
  );
}
```

### What if my webhook endpoint is down?

Vinr retries with exponential backoff:

- Immediate
- After 5 minutes
- After 30 minutes
- After 2 hours
- After 6 hours
- After 24 hours

Events are queued for up to 7 days.

### Can I receive webhooks in sandbox?

Yes, sandbox supports all webhook events with test data.

## Security

### How is card data transmitted?

- Production: Tokenized (PCI-compliant tokens)
- Option for raw card data (if you're PCI Level 1)
- Always over TLS 1.2+
- End-to-end encryption

Sandbox IPs:

### How often should I rotate API keys?

Recommended:

- Every 90 days for routine rotation
- Immediately if compromise suspected
- After personnel changes

### Are there any firewall requirements?

Allow outbound HTTPS (443) to:
- api.vinr.com
- webhooks.vinr.com
- cdn.vinr.com

## Testing

### How do I test in sandbox?

1. Use sandbox API keys (`bk_sandbox_...`)
2. Point to sandbox endpoint
3. Use test card numbers
4. Simulate webhook events

- Hourly (vs daily in production)
- Instant settlement available for testing
- Manual settlement trigger via API

## Performance

### What is the expected transaction volume?

Plan for:

- Average: 10-100 TPS
- Peak: 500 TPS
- Spikes during promotions/holidays

### How should I handle high load?

Recommendations:

- Horizontal scaling
- Connection pooling
- Caching where appropriate
- Async processing for non-critical operations
- Queue-based architecture

### What monitoring should I implement?

Monitor:

- API response times
- Error rates
- Authorization approval rates
- Webhook delivery success
- Settlement processing times
